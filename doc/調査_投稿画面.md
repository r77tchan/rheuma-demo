## Tiptap 3

`npm view` と、配布物（3.33.0）のソースで確認した。Context7 の資料は3.10と2系が混ざっていたので、APIの根拠はソースと型定義。組み合わせて動かしてはいない。

- パッケージはすべて 3.33.0、MIT。Pro（有料）の拡張は要らない。バージョンは揃える必要がある。
  - 入れたもの（9個）: `@tiptap/react` `@tiptap/pm` `@tiptap/core` `@tiptap/starter-kit` `@tiptap/extension-heading` `@tiptap/extension-link` `@tiptap/extension-list` `@tiptap/extension-image` `@tiptap/extension-text-style`
  - 見出し、リンク、箇条書きの項目は extend して使うので、パッケージを直接入れる（starter-kit は StarterKit しか export しない）。`@tiptap/extension-color` は `extension-text-style` の `Color` を出し直しているだけなので要らない。
  - `@tiptap/extension-file-handler` は使わない（下の「2026-11-09の確認」）。
  - `@tiptap/react` の peer は `react` / `react-dom` が `^17 || ^18 || ^19`。
- StarterKit（3系）の中身: Bold、Italic、Strike、Underline、Code、Blockquote、CodeBlock、HorizontalRule、HardBreak、Document、Paragraph、Text、Heading、BulletList、OrderedList、ListItem、ListKeymap、Link、UndoRedo、Dropcursor、Gapcursor、TrailingNode。
  - 要らないものは `StarterKit.configure({ italic: false, strike: false, ... })` で外す。
  - 見出しは `heading: { levels: [3] }`。貼り付けた h1 / h2 は段落になるはず（未確認）。
  - Link を別に足すと重複の警告が出る。Link を拡張するなら StarterKit 側を `link: false` にして、拡張した Link を渡す。
  - TrailingNode は末尾に空の段落を足す。残すなら、保存時に末尾の空段落を除く。
- 文字色: `TextStyle` と `Color`（どちらも `@tiptap/extension-text-style`）。出力は `<span style="color: #c00">`。`TextStyleKit` は背景色や文字サイズも入るので使わない。
  - パレットを限るオプションはない。色はボタンで固定の色だけ出す。貼り付けの色を外すには `Color.extend` で `parseHTML` に許可リストを通す（書き方は未確認）。
  - コマンドは `setColor('#039ea1')` / `unsetColor()`、今の色は `editor.getAttributes('textStyle').color`。
- 画像: `@tiptap/extension-image`。`inline`（既定 false）、`allowBase64`（既定 false）。
  - 注意: 読み込み対象が `img[src]` で、`data:` は除外。HTMLに `src` を付けずに `data-file-id` だけ残すと、読み込んだときに画像が消える。`src` を残すか、`parseHTML` を `img[data-file-id]` に差し替える。
  - 独自の属性は `Image.extend({ addAttributes() { return { ...this.parent?.(), fileId: { default: null, parseHTML: el => el.getAttribute('data-file-id'), renderHTML: a => a.fileId ? { 'data-file-id': a.fileId } : {} } } } })`。往復で消えないかは未確認。
  - 初期記事は `<p><img ...></p>`（段落の中）なので、`inline: true` にすると形が合う（こちらの判断。未確認）。
- ドラッグ＆ドロップと貼り付け: `@tiptap/extension-file-handler`（無料）。`allowedMimeTypes`、`onDrop(editor, files, pos)`、`onPaste(editor, files, html)`。
- PDF: 専用の拡張はない。Link マークに `fileId` を足して、文字のリンクとして入れる。Link の `isAllowedUri` は `blob:` を許さないので、エディタの中の `href` は仮の値にし、表示するときに差し替える。
- リンクの既定値は `target: '_blank'`、`rel: 'noopener noreferrer nofollow'`。元サイトに合わせて同じタブにするなら `HTMLAttributes` で変える。`openOnClick`（既定 true）は編集中に邪魔なので false。リンクのURLを入れる画面は自分で作る。
- Next.js / React 19:
  - `useEditor({ immediatelyRender: false, ... })` を明示する（戻り値は `Editor | null`）。
  - ツールバーの状態は `useEditorState({ editor, selector })` で読む（3系は、トランザクションごとに再描画しない）。
  - `setContent` の第2引数は、3系ではオプションのオブジェクト。
  - `next/dynamic` の `ssr: false` はサーバーコンポーネントから使えない（`lazy-loading.md`）。`"use client"` の部品の中で使う。
- 貼り付け: スキーマにない書式は落ちる。文字色は `<span style="color">` から読まれるので、Word などの色は入る。プレーンテキストにしたいときは `editorProps.transformPastedHTML`。
- 大きさ: 全部入りで minify 後 約421KB、gzip 後 約137KB。投稿画面だけで読み込む。

## ブラウザの保存とファイル

- `localStorage` は1オリジン約5MiB（UTF-16の文字数で数える）。超えると `QuotaExceededError`。本文に画像を base64 で入れると、すぐ上限に届く。
- IndexedDB には Blob ではなく、`ArrayBuffer` と形式を保存する（Safari で Blob の保存に失敗した報告と、プライベートで失敗する報告があるため。選んだ File は元のファイルを指すだけなので、元のファイルが変わると読めなくなる）。`arrayBuffer()` はトランザクションを開く前に読み切る（IndexedDB 以外の await で自動で完了してしまう）。容量はディスクの数割で、デモでは問題にならない。`navigator.storage.persist()` は呼ばない（確認のダイアログが出るのは Firefox だけで、効き目が小さい）。
- ライブラリ（idb-keyval など）は使わず、ブラウザの機能だけで書く（ユーザー確認済み）。サーバーでの描画で `indexedDB` に触らないよう、押したときの処理か `useEffect` の中で呼ぶ。
- Safari は、7日間サイトを操作しないと `localStorage` と IndexedDB の両方を消す。ホーム画面に追加すると保存場所が別になる。まれなので、投稿画面の注意書きには書いていない（「このブラウザにだけ保存されます」だけを出す）。
- blob URL（`URL.createObjectURL`）:
  - 作った文書が閉じるまで有効。実装では、作ったURLを文書ごとに使い回し、revoke しない（PDFのリンクを押したあと、新しいタブが読み込む前に revoke すると開けないため。数MBが数件なのでメモリは問題にならない）。
  - 同じオリジンの iframe と親で共有はできるが、作った文書に結びつくので、iframe の中では自分で IndexedDB を読んで作る。
  - PDF を `target="_blank"` で開くと、PCのブラウザは表示する。iPhone の Safari は白紙になる報告がある（未確認。5-2で実機確認）。白紙になるなら、PDFだけダウンロードのリンクにする。
  - 新しいタブのタイトルはファイル名にならない（変える方法がない）。ダウンロードの名前は `download` 属性で付けられる。

## 2026-11-09の確認

Tiptap は jsdom で動かした結果（[実行]）と、配布物のソースで確かめた結果。ブラウザは Web の一次資料（仕様、MDN、バグトラッカー）で調べた結果で、実機では見ていない。

- Tiptap（実装は `components/admin/editorExtensions.ts`）:
  - 見出しは `Heading.extend({ marks: "link" })`、`levels: [3]` で、h1 / h2 / h4 は段落になり、見出しの中の色と太字は外れる。見出しの中身を文字と改行だけにすると、画像のある段落を見出しにしたときに画像が黙って消えるので、そのときは見出しのボタンとショートカットを止めている。
  - 文字色の2色制限は、`Color` と `TextStyle` の両方を extend する（`TextStyle` だけだと、色のない `<span>` が残る）。出力は `rgb(...)` になる（ProseMirror が `style.cssText` で書くため）。読み込みは hex も rgb も受ける。`unsetColor` は文字を選んでいないと色のない文字スタイルを残すので、「色なし」は `unsetMark("textStyle")` にしている。
  - 画像は `img[data-file-id]` と、初期記事のダミー画像（src が完全一致）だけを読む。それ以外の img は、読み込みでも貼り付けでも消える。NodeView を付けても `getHTML()` に blob URL は出ない。
  - リンクは、HTMLに target / rel があると読み込んでしまうので、`addAttributes` で読み込みも書き出しもしないようにしている。autolink が有効だと、リンクの直後に打った文字もリンクになる（`inclusive()` が autolink の値を返す）ので無効にした。
  - 初期記事の本文は、読み込むと形が少し変わる（`<br />` が `<br>` に、`<li><a>` が `<li><p><a>` に、img の属性の順）。TrailingNode は、見出しや箇条書きで終わる本文に、最初の操作で空の段落を足す。そのため、読み込んだだけの形に戻ったときは元の文字列を返している（触っただけで「変更あり」にしない）。
  - `@tiptap/extension-file-handler` は、ファイルとHTMLが一緒に来る貼り付けで、HTMLの貼り付けも続けてしまう（`consumePasteEvent` の既定が false）。受け付けない形式は黙って捨てる。Word や Excel は文章と一緒に「見た目の画像」を入れることがあるので、自前で「HTMLに文字があれば通常の貼り付け、なければファイルを取り込む」にした。
  - `useEditor` は、ページが隠れる（Activity）とエディタを破棄し、表示し直すと作り直す（`@tiptap/react` のソース）。`useEditorState` が渡すエディタは、作った直後と作り直した直後には古いままなので、ツールバーの状態は `useEditor` が返すエディタから読む。
  - Tab で箇条書きが入れ子になる。ListItem を extend して Tab のキーを外し、中身を段落1つにした（片方だけだと例外が出る）。
- ブラウザ:
  - blob URL の PDF を `target="_blank"` で開く: Chrome の Blob URL Partitioning（M137〜M142）は、blob URL の site が移動を始めた文書と違うときだけ noopener を強制するので、同じオリジンのこのデモには当たらない。`rel="opener"` は付けない。
  - PDFを開いたタブは、元のページを閉じたあとに再読み込みすると表示できない見込み（未確認）。iPhone の Safari には、blob の PDF を新しいタブで開く不具合の履歴がある。5-2で実機確認する。だめなら同じタブで開く。
  - `crypto.randomUUID()` は https と localhost でしか使えない（LAN の http で実機から開くと存在しない）。ファイルIDは `getRandomValues` で作っている。
  - iPhone で写真を選ぶと、通常は JPEG に変換されて届く。写真ピッカーで「現在のもの」を選ぶと HEIC のまま届くので、HEIC は案内を出して受け付けない。
  - 画像の縦横は `createImageBitmap` で読む（EXIF の回転を反映する）。
  - 初期化は `objectStore.clear()`。`deleteDatabase` は、別のタブが接続を開いていると止まる。

## 元サイトの本文（本文のある記事132件をすべて取得）

- 使われているタグは `a`、`br`、`h3`、`h4`、`img`、`li`、`p`、`span`、`strong`、`ul` の10種だけ。`ol`、表、斜体、下線のタグ、`blockquote` はない。WordPress の旧エディタの出力。
- 見出し: `h3` が19（17記事）、`h4` は1記事だけ、`h2` は本文にない。実際には「`<p><strong>【移転先住所】</strong><br>…`」のように、太字＋改行で見出しにしている記事が多い。
- 文字色: `<span style="color">` だけ。青緑（`#039ea1` / `#05a6a6`）、赤とピンク（`#f73707` / `#fa3798` / `#f7077f`）、黒（`#000000`、実質は指定なし）。同じ「郵送」でもサイトごとに色の値が違い、手で選んでいる。
  - メインには `.page-content h3 span { font-size: 1.6rem; font-weight: normal }` があり、見出しに色を付けると、見出しの中の文字が16pxに小さくなる。`/senmon/` にはこの指定がなく、見た目がサイトで違う。
- リンク: 254個のうち `target="_blank"` は4個だけ。PDFへのリンクは5個で、文字のリンクだけ（アイコン、「（PDF）」、ファイルサイズの表記はない）。
- 画像: 4個（4記事）。すべて `<p>` の中の `<img>`（`alignnone`、`width` と `height` の属性付き、`figure` やキャプションはない）。1組はリンク付き。
- 箇条書き: `ul` が28個、入れ子なし。`<li><p>…</p></li>` が12個、`<li>…</li>` が16個。`li > p` の形だと、元サイトのCSSでは行間が広がる。手で打った「●」「・」の段落のほうが多い。
- `<br>` は56記事に119個（住所や連絡先）。末尾の `<p>&nbsp;</p>` が18記事にある（保存時に除いてよい）。全角スペースでの字下げも多い。
- こちらの `.article-body` は `p`、`a`、`h3`、`ul`、`strong`、`img` に元サイトと同じ見た目を付けてある。`h4` と `ol` の指定はない（使わないので不要）。
