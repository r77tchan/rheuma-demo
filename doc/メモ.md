## 決定事項

- 配色は元サイトと同じにする（ユーザー指定）。
- 文言: リンクやボタンの文言（ナビ、サイドメニュー、フッターのリンク、カテゴリ、見出しなど）は、「リウマチ」を含めて元サイトと同じにする。ロゴ、組織名とサイト名（「公益財団法人日本リウマチ財団」「リウマチ情報センター」など）、著作権表記、人名、記事や説明の文章、画像はダミーのままにする（ユーザー指定）。
- `/rheuma/` の文言: ヘッダーのサイト名と「患者さん・一般のみなさんへ」はダミー、吹き出しの「リウマチを知ろう！」は元サイトのまま。詳細のタイトルの丸い飾りは、画像を使わずCSSで描く（ユーザー確認済み）。
- `/senmon/` の文言: ヘッダーのサイト名と「医療関係者のみなさんへ」はダミー、トップの見出しの「医療関係者のみなさんへ」は元サイトのまま（`/rheuma/` の吹き出しと同じ扱い）。
- サブサイトのトップのグレーの枠: カードの外にある見出しは文字、カードとボタンはグレーにする。カードの中の見出しと、組織名が入る見出し（財団ニュース、医療機関）はグレーのまま（ユーザー確認済み）。
- `/senmon/` の初回の確認ポップアップは作らない。Pickup はスライダーにせず、カードを固定で並べる（ユーザー指定）。
- 動かないリンク: 行き先のないリンクは押しても動かないことが分かるようにする。ホバーでは禁止マークのカーソルにして、薄くせず色も変えない。押すと全幅でトースト「デモのため、このリンクは動きません」を出す。記事の直リンクと本文のリンクは `example.com` へ飛ぶまま、検索欄は入力できるまま（ユーザー確認済み）。
- 公開: 検索エンジンには載せない（`noindex`）。関係者にはURLで共有する（ユーザー指定）。
- 公開先は GitHub Pages（https://r77tchan.github.io/rheuma-demo/ ）。Vercel から移した。リポジトリの公開とURLの変更は了承済み（2026-11-09にユーザー決定）。
- 今後の目的は、発注元に「使いやすくする方法」を見せるイメージのデモ。本番は決まれば別プロジェクトで作る。ログイン情報も運用情報ももらえないので、課題はすべて公開ページからの推測として扱う。
- 作業の進め方: 慎重に進める。調査はしっかり行い、Sonnetのサブエージェントに任せる。設計、実装、レビューはOpusで行う。レビューは価値があるとき（データの保存まわりなど）だけ、別のエージェントで行う。設計を実装の前にレビューしてもよい。意味のない調査やレビューはしない。相談するときは、おすすめを付ける（ユーザー指定）。
- 計画とメモもAIが作ったものなので、疑ってよい。書いてあるとおりではなく、もっとよくできるならそう提案する（ユーザー指定）。

### デモの決定事項

- 再現度: サブサイトのお知らせまわりも、今のモックと同じ精度で作る（スマホ幅も元サイトに合わせる）。
- 直リンク記事: 元サイトのような本文が空の詳細ページは作らず、前後リンクでも飛ばす。一覧のクリック先は元サイトと同じ。
- 投稿画面: ログイン画面は付けない。スライダー枠は作らず、提案時に課題として触れる。
- 保存: DBは使わず、ブラウザ内に保存する（記事は `localStorage`、ファイルは IndexedDB）。入力した内容は別の端末には反映されない。「初期状態に戻す」ボタンを付ける。
- エディタ: Tiptap（3系、MIT、`react ^19` 対応を2026-11-06に確認）。1つの部品に閉じ込める。扱うのは段落、見出し、箇条書き、リンク、太字、文字色、画像、PDF。
- 記事の項目: ID、タイトル、公開日、種類（本文を書く / リンクだけ）、リンク先URL、本文HTML、掲載先（サイトごとのカテゴリ）。
- ダミー記事: 本文は文章のみ、文章とリンク、見出しとリンク、箇条書きのリンク、画像の5パターン。直リンクも多めに混ぜる（元サイトは約7割）。各サイトでページ送りが出る件数にする。
- 投稿の流れ: 種類を選ぶ、サイトごとに「載せない」かカテゴリを選ぶ、公開日を指定する、サイトごとのプレビューを見る、公開する。
- 掲載先の入力（2026-11-09にユーザー確認済み）: 3サイトとも、先頭に「載せない」を置いたラジオ1つにする（チェックボックスは使わない）。いつもどれか1つが選ばれていて、「載せない」に戻せば外せる。新規作成では3つとも「載せない」から始める。載せるサイトの枠は青くする（メインの枠が白いままなら、選び忘れに気づける。プレビューのタブにも載せるサイトだけが並ぶ）。全部「載せない」なら公開できない。公開ボタンの上に「載せる先」の一覧を出す案は、枠の色と同じ情報なのでやめた。
- 掲載先は自動では決めない（ユーザー確認済み）。元サイトでは、一般・患者さん情報の記事はほとんど `/rheuma/` にも、医療関係者情報の記事はほとんど `/senmon/` にも載っているが、公開ページからの推測で、運用のルールかは分からない。選んでいない欄が勝手に変わると分かりにくいので、メインのカテゴリから初期値を入れる機能はやめた。載せ忘れには、枠の色とプレビューのタブで気づける。運用のルールが決まっていれば初期値を入れられることは、提案のときに口頭で触れる。

#### 投稿画面の詳細（2026-11-08にユーザー確認済み）

- 初期記事も編集、削除できる。確認（離れる、削除、初期状態に戻す）はブラウザのダイアログではなく、画面の真ん中に出すダイアログ（`components/admin/ConfirmDialog.tsx`）にそろえる。その場で表示を置き換える形だと、行やヘッダーの高さが変わって画面がずれるため。下書きと予約投稿は作らない。公開日は表示に使うだけで、未来の日付でもすぐ全サイトに出す（元サイトの WordPress でも予約はできるので、デモで見せる価値が小さい。2026-11-09にユーザー確認済み）。公開せずに準備しておく方法がないことは、提案のときに口頭で触れる。
- メインに載せず、サブサイトだけに載せる記事も作れる（メインのカテゴリに「メインには載せない」を足す）。
- 保存: 追加、編集した記事と、削除した初期記事のIDだけを保存し、キーにバージョンを付ける。形式が変わったら古いデータは捨てて初期状態に戻す（移す処理は作らない）。
- プレビュー: 実際のページを投稿画面の中のiframeに表示し、サイト3つと幅（PC / スマホ）を切り替える。本文の記事は詳細ページとトップの新着欄、リンクだけの記事はトップの新着欄を出す。
- 公開したあとは「公開しました」と、各サイトの記事へのリンクを出す。
- 入り口: サイト側には投稿画面へのリンクを置かず、`/admin/` のURLを共有する。投稿画面のヘッダーの右から各サイトへ飛べる（別のタブで開くマーク付き。「サイトを見る」などの説明の文は付けない）。
- リンクだけの記事にPDFを添付する機能は作らない（URLの入力だけ）。提案のときに触れる。
- サイトごとにタイトルや本文を変える機能は作らない（1つの内容を全サイトで共有する）。
- 見た目: 白地にメインの青を差し色にしたシンプルな管理画面。PCは左に入力欄、右にプレビュー。スマホは縦に並べ、崩れない程度にする。迷わない並びと文言を優先し、見れば分かる説明の文は出さない。押すと何かが起きるボタン（新規作成、公開する）は青の塗りつぶし、選択中のタブや絞り込みは薄い青（`components/admin/ui.ts` の `toggleClass`）にして見分けられるようにする。別のタブで開くリンクにはマークを付ける（`ExternalLinkIcon`）。投稿画面の押せるボタンは指のカーソルにする（Tailwind CSS 4 はボタンのカーソルを矢印のままにするので、`app/globals.css` の `.admin-ui` で指定）。
- 細部: 新しい記事のIDは1000から始まる数字の連番。公開日の初期値は今日で、時刻は扱わない。ファイルは1つ5MBまで。画像は JPEG、PNG、GIF、WebP（SVG と HEIC は案内を出して受け付けない）。見出しのレベルと文字色は元サイトの本文に合わせる。
- エディタの書式（元サイトの本文132件の調査から）: 見出しは `h3` だけ。文字色は青緑 `#039ea1` と赤 `#f73707` の2色と「色なし」で、貼り付けた色も2色以外は外す。見出しの中には色も太字も付けられない。改行（Shift+Enter）は使える。リンクは同じタブで開く。PDFは文字のリンクだけ（アイコンなし）。
- エディタの細部（2026-11-09にユーザー確認済み）:
  - PDFだけは別のタブで開く。blob URL はそのページが開いているあいだだけ使えるので、同じタブで開くとPDFの画面で再読み込みしたときに表示できなくなる。本番は普通のURLになるので、元サイトどおり同じタブにできる。
  - 箇条書きはエディタでは必ず `<li><p>…</p></li>` になるので、`li > p` に余白を付けず、元サイトで多い `<li>…</li>` と同じ見た目にする。入れ子は作れない（元サイトにない）。
  - 貼り付けた他のサイトの画像（URL）は外す。初期記事のダミー画像だけは残す。
  - 画像のある段落では、見出しのボタンを押せない（見出しにすると画像が消えるため）。カーソルが見出しか箇条書きの中のときは、画像をそのブロックの後ろに入れる。
  - 打ったURLの自動リンクと、「### 」「- 」などで書式が変わる機能は使わない。文字を選んでURLを貼るとリンクになるのは残る。
  - 編集画面では、PDFのリンクに小さく「PDF」と出す（サイトには出ない）。
  - 取り込みの途中は公開できない。タイトルなどの欄の Enter では公開しない。
- プレビューの中のリンクは押しても移動しない（注意書きは出さない。プレビューだと分かれば不具合には見えないため）。トップは新着欄の位置まで自動でスクロールする。
- 公開したあとは一覧に戻り、上に「公開しました」と各サイトの記事へのリンクを出す。
- 入力の途中で離れるとき: 投稿画面の中のリンクでは画面の中で確認、タブを閉じる・再読み込みはブラウザの確認。戻るボタンでは確認しない。GitHub Pages への移行で Cache Components を外したので、戻ると入力は消え、進むでも戻らない（前は隠れて残った画面から戻った）。
- ヘッダーの下に、小さな灰色の文字で「デモのため、入力した内容はこのブラウザにだけ保存されます（ほかの人には見えません）」と出し、その横に「初期状態に戻す」を置く（デモのためだけのものをまとめる。URLで共有するので、相手の画面に出ないという誤解を防ぐ）。Safari の7日間の話は書かない。ヘッダーには「記事一覧」「新規作成」のリンクを置かない。入力画面の「記事一覧に戻る」は、上の文字のリンク（← 記事一覧に戻る）だけにする（画面を移るものはリンク、その場で実行するものはボタン。下の並びは公開と削除だけ）。
- 一覧画面: 全件を新しい順に、サイトで絞り込める。ページ送りなし。編集した記事に「編集済み」の印。新規作成のボタンは右上。
- 表示中にエラーが起きたら、「初期状態に戻す」ボタン付きのエラー画面を出す。
- iPhoneでのPDFと縮小プレビューの確認は、5-2でユーザーに実機で見てもらう。
- 別のタブで削除された記事を、開いたままの編集画面から保存したときは、保存せず「この記事は削除されています」と出す（初期記事も同じ。元に戻さない）。
- 投稿画面でのサイトの呼び方は役割にする（メインサイト / 一般・患者さん向けサイト / 医療関係者向けサイト。正式名はダミーのため）。投稿画面からサイトへのリンクは別のタブで開く。
- 「初期状態に戻す」のあとは、IDを1000から使い直す。別のタブで古い編集画面を開いたまま初期化して新しく記事を作ると、古い画面の保存で上書きされうるが、デモではまず起きないので認める。
- 作り: 画像とPDFは IndexedDB（ライブラリなし）。本文のHTMLにはファイルのIDだけを残し、表示するときにURLに差し替える。どの記事も使っていないファイルは保存のたびに消す。ただし、取り込んでから24時間は残す（戻るボタンで離れた入力画面は隠れて残るので、そのあいだに別の記事を保存しても、入力中の画像が消えないようにする。ユーザー確認済み）。プレビューは同じサイトのページをiframeで開き、iframe側の準備ができてから `postMessage` で下書きを送る。PC幅は1440pxのページを縮めて表示する。
- 5-1の進め方: (1) 本番ビルドで、ビルド時にIDが分からない記事の詳細ページを確かめる (2) 保存まわりとエラー画面、レビュー (3) 投稿画面とプレビュー（リンクだけの記事） (4) エディタ、画像とPDF、レビュー。段階ごとにユーザーに確認してもらう。

### 実装の注意

- 静的な書き出しでは、ビルドのときに作ったページしか開けない。投稿画面で追加した記事のIDや増えたページ番号はビルドのときに分からないので、URLのクエリに持たせる（`/news/detail/?id=45`、`/news/?page=2`、`/admin/edit/?id=45`。URLは `lib/newsUrls.ts` で作る）。記事のページは各サイトに1枚だけ書き出し、`components/news/QueryPages.tsx`（投稿画面は `EditArticleFromQuery`）が `useSearchParams` でクエリを読んで、中身をブラウザで組み立てる。`useSearchParams` を使う部品は `Suspense` に包む（ないとビルドが落ちる。`use-search-params.md`）。同じページのままクエリだけ変わる移動（前後の記事、ページ送り、戻る）で前の状態が残らないよう、`key` にIDやページ番号を渡す。カテゴリ別のページは決まった数なので、今までどおりパス（`/news-list/{カテゴリ}/`）。
- 「記事がない」は `useHydrated()` が true になってから判定する。ブラウザのデータを読む前に判定すると、投稿した記事まで「ない」と出る。
- トップと下層の出し分けに `usePathname` を使わない。Cache Components を使っていたころは、レイアウトで使うとビルド時にIDが分からないページで止まった（`use-pathname.md`）。メインは `(home)` と `(lower)` にレイアウトを分けて、`MainSiteShell` に渡している。サブサイトでトップと下層の見た目が違うときも同じ形にする。`/rheuma/` は同じ見た目なので、`app/rheuma/layout.tsx` の1つだけ。`/senmon/` はフッターの線だけ違うので、`app/senmon/(home)` と `(lower)` に分けている。
- Cache Components が有効だと、ページ移動後も前の画面の状態が残る（`preserving-ui-state.md`）。GitHub Pages への移行で外したので今は起きないが、下の対応はそのまま残してある（害はない。サーバーのある配信に戻して有効にするときに要る）。開いたメニューが残らないよう、`lib/useFullMenu.ts` で別のレイアウトへ移るときに `useLayoutEffect` で閉じ、同じレイアウト内の移動に備えて、メニュー内のリンクを押したときと、戻る、進むを押したとき（`popstate`）にも閉じる（動作を確認済み）。ヘッダーは同時に複数DOMに残るので、メニューのIDは `useId` で作る。
- ブラウザ内のデータの読み取りは `lib/useScrolledPast.ts` と同じ `useSyncExternalStore` の形にする。
- 2026-11-06の調査で取得したHTMLはセッションの作業領域にあり、次のセッションでは使えない。必要な値は `doc/調査_お知らせ.md` にあり、足りない分はその場で測り直す。

## モックの実装

- お知らせの記事は `data/news.ts`（型、カテゴリ、初期記事）と `lib/newsStore.ts`（読み書き）にある。画面からは `useSiteArticles(サイト)` で読む。
- 保存データ（`localStorage` の `rheuma-demo:news:v1`）は初期記事との差分だけ。`parseArticle` が「保存できる記事の形」の定義で、読むときも保存するときも通す。記事に項目を足すときは、`parseArticle` とキーの番号も一緒に変える（足し忘れると、その項目は次の保存で消える）。保存の関数は `SaveResult`（失敗の理由は `invalid` / `not-found` / `storage`）を返す。
- プレビューの下書きは `setPreviewDraft` でストアに重ねる（保存はしない）。受け取った値は `parseArticle` を通す。
- 保存まわりの確認は、`react` をスタブに差し替えて Node で関数を直接動かすテストで行った（プロジェクトには入れていない）。表示中のエラーは `app/error.tsx` が受け、「初期状態に戻す」を出す。
- 投稿画面は `app/admin/` と `components/admin/`。枠は `AdminFrame`、記事一覧は `ArticleList`、入力画面は `ArticleEditor`、本文のエディタは `BodyEditor` と `editorExtensions.ts`、プレビューは `PreviewPane`。保存したあとのお知らせは `lib/adminFlash.ts`（モジュールに持つだけで保存しない。読み込み直すときだけ sessionStorage で渡す）。画面はハイドレーションのあとで描く（`useHydrated`）。
- 画像とPDF: 保存は `lib/fileStore.ts`（IndexedDB の `rheuma-demo:files`。中身は ArrayBuffer、`createdAt` の索引で古い未使用ファイルを探す）、本文のHTMLの処理は `lib/bodyHtml.ts`、サイトでの表示は `components/news/ArticleBody.tsx`。作った blob URL は文書ごとに使い回し、revoke しない。ファイルを使っていない本文は、今までどおりサーバーでも描く。
- 本文のエディタ（Tiptap 3.33.0、9パッケージ）は、「本文を書く」を選んだときだけ `next/dynamic` で読み込む（サイト側のページでは読み込まない）。拡張は `editorExtensions.ts` で1回だけ作る（作り直すと useEditor が setOptions を呼ぶ）。
- Tiptap は読み込むときに本文の形を少し変える（`<br />` を `<br>` に、`<li><a>` を `<li><p><a>` に、など）。読み込んだだけの形に戻ったときは元の文字列を返し、触っただけで「変更あり」「編集済み」にしない（`BodyEditor` の baseline）。
- 下のActivity（隠れて残る画面）への対応は、Cache Components を外した今は働かないが、残してある。
- ページが隠れる（Activity）と、`useEditor` はエディタを破棄し、表示し直すと作り直す。作り直したときは入力中の本文を入れ直す（元に戻す履歴には入れない）。`useEditorState` が渡すエディタは作った直後には古いままなので、ツールバーの状態は `useEditor` が返すエディタから読む。
- 入力画面は、開いたあとで記事が変わったら（別のタブで更新、削除、初期化など）、入力の途中でなければ今の記事で作り直す（隠れて残った画面に古い記事を出さないため）。「初期状態に戻す」（`components/admin/DemoNotice.tsx`）のあとは、どの画面からでも一覧を文書ごと読み込み直す（隠れた入力画面と、覚えている blob URL をまとめて消す）。入力の途中でも、ブラウザの離れる確認は出さない（`allowLeaveWithoutConfirm`）。
- ファイルを落としたときにページが移動しないよう、`AdminFrame` と `PreviewReceiver`（iframe の中）で window の drop を止めている（`lib/blockFileDrop.ts`）。エディタの中のPDFのリンクは href を持たないので、`DummyLinkToast` と禁止マークのカーソルの対象から外している。
- ページは移動後も隠れて残る（Activity）。入力画面は、保存、削除、「離れる」のときに `key` を変えて作り直し、前の入力を残さない。離れるときの確認（`LeaveGuard.tsx`）は `useLayoutEffect` で登録し、ページが隠れたら外れる。隠れたページの DOM も残るので、`querySelector` はフォームの中に絞る。
- プレビューの流れ（`lib/preview.ts`）: iframe の `name` が `news-preview` のページでだけ、ルートレイアウトの `PreviewReceiver` が働く。準備ができたら ready を送り、投稿画面は ready を受けてから下書きを送る。iframe の中ではリンクを押しても移動しない（`window` の capture で止める）。新着欄までのスクロールは、3サイトの新着欄に付けた `data-preview-anchor="news"` が目印。
- `ResizeObserver` は、ページが隠れると大きさ0を報告する。0のときは前の大きさのままにしないと、縮小率の計算が0÷0になる（実際に起きた）。

## 確認のしかた

- 元サイトは https://www.rheuma-net.or.jp/ 。
- 元サイトとの比較は、Chromeで同じ幅に揃えて各ブロックの座標を測って行う（下層ページは1440 / 900 / 390px）。
- 座標が揃っても、書体や太さ、色の差は見つからない。文字の要素は、同じ文言の要素を両方のサイトで探して、書体、サイズ、太さ、色、字間も比べる。
- 2026-11-06時点のトップの高さの差（こちらが高い）: 900pxで11px（スライダー）、390pxで78px（メインビジュアル約25px、挨拶約36px、バナー約18px）。1440pxと500pxはほぼ一致。お知らせ欄は1440 / 900 / 500pxで一致している。
- 自分のコードの変更前後は、全要素の座標を記録して比べる（`doc/測定スクリプト.md`）。
- エディタの確認: ファイルは JS で作り（canvas の `toBlob`、PDFは最小の文字列）、`DataTransfer` でファイルの入力欄に入れて `change` を送る。貼り付けとドロップは `ClipboardEvent` / `DragEvent` に `DataTransfer` を付けて送れば、ProseMirror が受ける。エディタは `document.querySelector('.ProseMirror').editor` で触れる。Tiptap の `commands.focus()` は少し遅れてフォーカスを戻すので、そのあとに開いた入力欄からフォーカスを奪う（確認では `editor.view.focus()` を使う）。HTMLに `=` などがあると結果が伏せられるので、置き換えてから返す。
- Chromeのウィンドウは幅500pxまでしか縮まず、縮まないこともある。スマホ幅は、元サイトのページ内にJSで同じサイトのiframe（幅390pxなど）を置けば確認できる（`frame-ancestors 'self'` なので同じサイト内なら表示される）。
- サイト名や記事の中身に元サイトの文言が混ざっていないかは、表示文字列を元サイトのHTMLと照合して確認する。リンクやボタンの文言は対象外。
