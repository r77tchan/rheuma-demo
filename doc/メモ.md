## 決定事項

- 配色は元サイトと同じにする（ユーザー指定）。
- 文言: リンクやボタンの文言（ナビ、サイドメニュー、フッターのリンク、カテゴリ、見出しなど）は、「リウマチ」を含めて元サイトと同じにする。ロゴ、組織名とサイト名（「公益財団法人日本リウマチ財団」「リウマチ情報センター」など）、著作権表記、人名、記事や説明の文章、画像はダミーのままにする（ユーザー指定）。
- `/rheuma/` の文言: ヘッダーのサイト名と「患者さん・一般のみなさんへ」はダミー、吹き出しの「リウマチを知ろう！」は元サイトのまま。詳細のタイトルの丸い飾りは、画像を使わずCSSで描く（ユーザー確認済み）。
- `/senmon/` の文言: ヘッダーのサイト名と「医療関係者のみなさんへ」はダミー、トップの見出しの「医療関係者のみなさんへ」は元サイトのまま（`/rheuma/` の吹き出しと同じ扱い）。
- サブサイトのトップのグレーの枠: カードの外にある見出しは文字、カードとボタンはグレーにする。カードの中の見出しと、組織名が入る見出し（財団ニュース、医療機関）はグレーのまま（ユーザー確認済み）。
- `/senmon/` の初回の確認ポップアップは作らない。Pickup はスライダーにせず、カードを固定で並べる（ユーザー指定）。
- 公開: 検索エンジンには載せない（`noindex`）。関係者にはURLで共有する（ユーザー指定）。
- 今後の目的は、発注元に「使いやすくする方法」を見せるイメージのデモ。本番は決まれば別プロジェクトで作る。ログイン情報も運用情報ももらえないので、課題はすべて公開ページからの推測として扱う。

### デモの決定事項

- 再現度: サブサイトのお知らせまわりも、今のモックと同じ精度で作る（スマホ幅も元サイトに合わせる）。
- 直リンク記事: 元サイトのような本文が空の詳細ページは作らず、前後リンクでも飛ばす。一覧のクリック先は元サイトと同じ。
- 投稿画面: ログイン画面は付けない。スライダー枠は作らず、提案時に課題として触れる。
- 保存: DBは使わず、ブラウザ内に保存する（記事は `localStorage`、ファイルは IndexedDB）。入力した内容は別の端末には反映されない。「初期状態に戻す」ボタンを付ける。
- エディタ: Tiptap（3系、MIT、`react ^19` 対応を2026-11-06に確認）。1つの部品に閉じ込める。扱うのは段落、見出し、箇条書き、リンク、太字、文字色、画像、PDF。
- 記事の項目: ID、タイトル、公開日、種類（本文を書く / リンクだけ）、リンク先URL、本文HTML、掲載先（サイトごとのカテゴリ）。
- ダミー記事: 本文は文章のみ、文章とリンク、見出しとリンク、箇条書きのリンク、画像の5パターン。直リンクも多めに混ぜる（元サイトは約7割）。各サイトでページ送りが出る件数にする。
- 投稿の流れ: 種類を選ぶ、カテゴリを選ぶと掲載先の初期値が入る、公開日を指定する（予約投稿）、サイトごとのプレビューを見る、公開する。
- 掲載先の初期値: 一般・患者さん情報は `/rheuma/` にも、医療関係者情報は `/senmon/` にも載せる。財団情報は規則がないので毎回選ぶ。サブサイト側のカテゴリは掲載先ごとに指定が要る。

### 実装の注意

- 投稿画面で作った記事のIDはビルド時に分からないので、詳細ページはブラウザ側で組み立てる。初期記事は `generateStaticParams` で事前に作り、`Suspense` の中で `params` を読む（`app/(main)/(lower)/news/[id]/page.tsx`）。`generateStaticParams` は空だとビルドエラーになり、`dynamicParams` は使えない。
- 「記事がない」は `useHydrated()` が true になってから判定する。ブラウザのデータを読む前に判定すると、投稿した記事まで「ない」と出る。
- トップと下層の出し分けに `usePathname` を使わない。レイアウトで使うと、ビルド時にIDが分からないページで止まる（`use-pathname.md`）。メインは `(home)` と `(lower)` にレイアウトを分けて、`MainSiteShell` に渡している。サブサイトでトップと下層の見た目が違うときも同じ形にする。`/rheuma/` は同じ見た目なので、`app/rheuma/layout.tsx` の1つだけ。`/senmon/` はフッターの線だけ違うので、`app/senmon/(home)` と `(lower)` に分けている。
- Cache Components が有効だと、ページ移動後も前の画面の状態が残る（`preserving-ui-state.md`）。開いたメニューが残らないよう、`lib/useFullMenu.ts` で別のレイアウトへ移るときに `useLayoutEffect` で閉じ、同じレイアウト内の移動に備えて、メニュー内のリンクを押したときと、戻る、進むを押したとき（`popstate`）にも閉じる（動作を確認済み）。ヘッダーは同時に複数DOMに残るので、メニューのIDは `useId` で作る。
- ブラウザ内のデータの読み取りは `lib/useScrolledPast.ts` と同じ `useSyncExternalStore` の形にする。
- 2026-11-06の調査で取得したHTMLはセッションの作業領域にあり、次のセッションでは使えない。必要な値は `doc/調査_お知らせ.md` にあり、足りない分はその場で測り直す。

## Next.js（16.4.5）

- `create-next-app` は初期設定で `AGENTS.md` を生成する。作り直すときは `--no-agents-md` を付ける。
- `next dev` はAIエージェントを検出すると、既存の `AGENTS.md` の末尾に指示ブロックを書き足す（実測で確認）。`next.config.ts` の `agentRules: false` で防いでいる。この行を消すと、また書き足される。同じ趣旨の指示は、代わりに `doc/指示.md` に書いてある。
- 新しいルートを足した直後は、`PageProps` や `LayoutProps` の型がまだ生成されていないので `tsc` が落ちる。`next build` のあとなら通る。
- 初期設定で Cache Components と Partial Prefetching が有効。データ取得は既定で動的で、キャッシュしたい箇所に `use cache` を付ける。動的な要素を入れるときに確認する。

## モックの実装

- お知らせの記事は `data/news.ts`（型、カテゴリ、初期記事）と `lib/newsStore.ts`（読み書き）にある。画面からは `useSiteArticles(サイト)` で読む。メインの見出しとリンクの文言は `data/site.ts` の `news`、`/rheuma/` は `data/rheuma.ts`、`/senmon/` は `data/senmon.ts`。
- サイトごとの違いの置き場所: 値は `data/news.ts` の `siteNews`。見た目は `PageTitle`、`ArticleHeading`、`sectionMargins`。サイトだけの部品は `components/rheuma/` と `components/senmon/`。
- サブサイトの部品は、共通の部品を組み合わせて作る: `SubSiteHeader`（ナビの項目は `children` に `li` で渡す）、`FullMenuPanel`、`MenuGroup`、`SideMenu`（`items`）、`Footer`（`logoHref` など）。
- サイトの色は `app/globals.css` の `.theme-rheuma` で `--color-brand` を上書きしている。この中では `bg-brand` や `text-brand` が `#3293b1` になる。本文のリンクの色や見出しの太さの違いも同じ場所に書く。`/senmon/` はメインと同じ `#0056ad` なので、テーマの指定はない。
- `/rheuma/` の初期記事のIDは、新しい10件が299〜290、古い12件が199〜188。共通の記事は1〜45のまま。公開日の年（2001 / 2000 / 1999年）で一覧の並びを決めているので、`/rheuma/` だけの記事を足してもメインは変わらない。296は元サイトの記事13456と文字数を揃えた比較用（本文の型 `notice`）。
- `/senmon/` の初期記事のIDは、新しい10件が399〜390、古い7件が379〜373。377は元サイトの記事3169と文字数を揃えた比較用（本文の型 `text`）。一番新しい本文記事の398には「次の記事へ」が出ないので、比較には使わない。
- サブサイトのトップのグレーの枠は、3つの幅に合わせた固定の高さ。他の幅では元サイトとずれる。
- 元サイトの `/rheuma/` は、ページタイトルとパンくずが「What’s new」（丸い引用符）、トップとメニューが「What's new」。こちらも同じにしてある。`/senmon/` はどこも丸い引用符で、全画面メニューの項目は「お知らせ」。
- 元サイトの `/rheuma/` のヘッダーはPC幅で `min-width: 1670px` なので、1670px未満では右端の「医療機関」とXが切れる。こちらも同じ。1024px以下ではナビがないので、この指定は外している。`/senmon/` は `1640px` で同じ扱い。元サイトはスマホ幅でもこの指定で横スクロールが出るが、こちらは出ない。
- メインから `/rheuma/` と `/senmon/` へのリンクは、右のメニュー、トップの案内ボタン、全画面メニューの3か所。元サイトは別タブで開くが、こちらは同じタブで開く。
- 今日の日付は `lib/newsStore.ts` でブラウザ側でだけ読む。ビルド時の描画で `new Date()` を読むとビルドエラーになる（`migrating-to-cache-components.md`）。サーバーでの描画では日付で絞らないので、初期記事は過去の日付にする。
- 正式な組織名を含む文言（スライダー4枚目の「日本リウマチ財団【公式】X」など）はダミーのまま。「リウマチ財団について」のような短いメニュー名は元サイトのまま。「Whats's new」は元サイトの綴りのまま。
- ダミー記事のタイトルは `data/news.ts` の `dummyTitles` を文字数で引く。先頭10件は、元サイトの一覧と折り返しの行数が同じになる文字数にしてある。元の文に半角が多いと幅が変わるので、文字数をそのまま使わない（`/senmon/` の先頭は34文字の代わりに28文字、60文字の代わりに52文字）。
- URLは `trailingSlash: true` で末尾の `/` に揃えている。
- 明朝は元サイトと同じ指定（`Source Han Serif JP` から始まる）で、Webフォントは読み込まない。端末にある書体で表示されるので、Macでは游明朝になる。
- `noindex` は開発サーバーのHTMLには出なかったが、本番ビルドでは出る（理由は未確認）。確かめるときは本番ビルドで見る。
- 存在しないカテゴリは `(lower)/not-found.tsx` で他の「見つからない」と同じ案内を出す。本番のステータスは200のまま（部分的に事前生成されたページは応答の開始後に判定するため）。
- 元サイトと同じ弱点: 約360px未満の幅では、一覧のカードで日付とバッジが重なる（そのままにしている）。ページ送りは元サイトだと7ページ以上の途中ではみ出すが、こちらは折り返す。
- ダミー文言の文字数は元の文に揃えている。文字数を変えると折り返しが変わり、高さがずれる。
- PC幅（1025px〜）は元サイトと同じく `min-width: 1370px`。1025〜1369pxでは横スクロールが出る。
- 元サイトと変えた点: スライダーの矢印は作っていない（元サイトは白色で見えない）。最後のスライドの次は巻き戻して先頭へ戻る。全画面メニューの高さは下端が切れないよう調整した。子メニューの開閉はスマホ幅だけ。`/senmon/` の Pickup は、PC幅で4枚を幅いっぱいに並べる（幅約284px。元サイトは273pxで5枚目が少し見える）。

## 確認のしかた

- 元サイトは https://www.rheuma-net.or.jp/ 。
- 元サイトとの比較は、Chromeで同じ幅に揃えて各ブロックの座標を測って行う（下層ページは1440 / 900 / 390px）。
- 座標が揃っても、書体や太さ、色の差は見つからない。文字の要素は、同じ文言の要素を両方のサイトで探して、書体、サイズ、太さ、色、字間も比べる。
- 2026-11-06時点のトップの高さの差（こちらが高い）: 900pxで11px（スライダー）、390pxで78px（メインビジュアル約25px、挨拶約36px、バナー約18px）。1440pxと500pxはほぼ一致。お知らせ欄は1440 / 900 / 500pxで一致している。
- 自分のコードの変更前後は、全要素の座標を記録して比べる（`doc/測定スクリプト.md`）。
- Chromeのウィンドウは幅500pxまでしか縮まず、縮まないこともある。スマホ幅は、元サイトのページ内にJSで同じサイトのiframe（幅390pxなど）を置けば確認できる（`frame-ancestors 'self'` なので同じサイト内なら表示される）。
- サイト名や記事の中身に元サイトの文言が混ざっていないかは、表示文字列を元サイトのHTMLと照合して確認する。リンクやボタンの文言は対象外。
