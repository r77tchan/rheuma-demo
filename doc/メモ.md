# メモ

次回のセッションに活きる学びなどを書く。

## 決定事項

- 配色は元サイトと同じにする（ユーザー指定）。
- 文言: カテゴリ名とボタンなどの文言は元サイトと同じにする。サイト名、ロゴ、記事の中身はダミーのままにする（ユーザー指定）。
- 今後の目的は、発注元に「使いやすくする方法」を見せるイメージのデモ。本番は決まれば別プロジェクトで作る。ログイン情報も運用情報ももらえないので、課題はすべて公開ページからの推測として扱う。

## 進行計画（デモ）

「お知らせを1回入力すれば3サイトに載る」というイメージを見せるデモを作る。作業ブランチは `news-demo`。`main` へのプッシュで公開URLが更新されるので、セッション5まで `main` には入れない。

1セッションで1行ずつ進める。終わったらユーザーに見てもらい、確認が取れたらコミットして、下の表とメモを更新する。

| セッション | 内容 | 状態 |
| --- | --- | --- |
| 1 | 土台づくり | 未着手 |
| 2 | メインの一覧と詳細 | 未着手 |
| 3 | `/rheuma/` のお知らせまわり | 未着手 |
| 4 | `/senmon/` のお知らせまわり | 未着手 |
| 5 | 投稿画面、README更新、`main` への反映 | 未着手 |
| 6 | `/rheuma/` のトップ全体 | 5のあとに通しで見て、やるか決める |
| 7 | `/senmon/` のトップ全体 | 同上 |

### 各セッションの内容

1. 土台づくり。見た目が変わるのは文言とカテゴリだけ。
   - トップの見出しを「お知らせ」、リンクを「もっとみる」にする。カテゴリを財団情報 `bg-sky`、一般・患者さん情報 `bg-pink`、医療関係者情報 `bg-teal` にする。
   - `Header`、`SideMenu`、`Footer` を共通レイアウトへ移す。`pc:min-w-[1370px]` もルートレイアウトの `body` から移す（投稿画面には不要）。
   - 記事データの読み書きを1か所にまとめる。`data/site.ts` の「参考サイトの文言は使わない」というコメントは今の方針に直す。
2. メインの一覧、カテゴリ別、詳細。ダミー記事を用意し、3つの幅で座標を測って元サイトに揃える。
3. `/rheuma/` のヘッダー、フッター、サイドメニュー、新着欄、一覧、詳細。メニューは開閉の動きも作る。トップの他の部分はグレーの枠。3つの幅で測って揃える。
4. `/senmon/` について3と同じ。
5. 投稿画面。公開すると、選んだサイトに記事が出るところまで作る。READMEを今の内容に直す。
6. グレーの枠を、元サイトのレイアウトの再現に置き換える。
7. 6と同じ。

### 作るページ

| サイト | URL |

| メイン | `/`、`/news/`、`/news/page/{n}/`、`/news-list/{カテゴリ}/`、`/news/{id}/` |
| `/rheuma/` | `/rheuma/`、`/rheuma/news/`、`/rheuma/news/page/{n}/`、`/rheuma/news/{id}/` |
| `/senmon/` | `/senmon/`、`/senmon/news/`、`/senmon/news/page/{n}/`、`/senmon/news-list/{カテゴリ}/`、`/senmon/news/{id}/` |
| 投稿画面 | `/admin/`、`/admin/new/`、`/admin/{id}/` |

`/rheuma/` のカテゴリ別ページは、元サイトでも白紙でリンクもないので作らない。

### デモの決定事項

- 再現度: サブサイトのお知らせまわりも、今のモックと同じ精度で作る（スマホ幅も元サイトに合わせる）。
- 直リンク記事: 元サイトのような本文が空の詳細ページは作らず、前後リンクでも飛ばす。一覧のクリック先は元サイトと同じ。
- 投稿画面: ログイン画面は付けない。スライダー枠は作らず、提案時に課題として触れる。
- 保存: DBは使わず、ブラウザ内に保存する（記事は `localStorage`、ファイルは IndexedDB）。入力した内容は別の端末には反映されない。「初期状態に戻す」ボタンを付ける。
- エディタ: Tiptap（3系、MIT、`react ^19` 対応を2026-11-06に確認）。1つの部品に閉じ込める。扱うのは段落、見出し、箇条書き、リンク、太字、文字色、画像、PDF。
- 記事の項目: ID、タイトル、公開日、種類（本文を書く / リンクだけ）、リンク先URL、本文HTML、掲載先（サイトごとのカテゴリ）。
- ダミー記事: 本文は文章のみ、文章とリンク、見出しとリンク、箇条書きのリンク、画像の5パターン。直リンクも多めに混ぜる（元サイトは約7割）。各サイトでページ送りが出る件数にする。
- 投稿の流れ: 種類を選ぶ、カテゴリを選ぶと掲載先の初期値が入る、公開日を指定する（予約投稿）、サイトごとのプレビューを見る、公開する。
- 掲載先の初期値: 一般・患者さん情報は `/rheuma/` にも、医療関係者情報は `/senmon/` にも載せる。財団情報は規則がないので毎回選ぶ。サブサイト側のカテゴリは掲載先ごとに指定が要る。

### 実装の注意

- 投稿画面で作った記事のIDはビルド時に分からないので、詳細ページはブラウザ側で組み立てる。`generateStaticParams` と `Suspense` の扱いは `dynamic-routes.md` の「With Cache Components」を読む。
- Cache Components が有効だと、ページ移動後も前の画面の状態が残る（`preserving-ui-state.md`）。開いたメニューが残らないよう閉じる処理を入れる。
- ブラウザ内のデータの読み取りは `lib/useScrolledPast.ts` と同じ `useSyncExternalStore` の形にする。
- 2026-11-06の調査で取得したHTMLはセッションの作業領域にあり、次のセッションでは使えない。必要な値はこのメモにあり、足りない分はその場で測り直す。

## Next.js（16.4.5）

- `create-next-app` は初期設定で `AGENTS.md` を生成する。作り直すときは `--no-agents-md` を付ける。
- `next dev` はAIエージェントを検出すると、既存の `AGENTS.md` の末尾に指示ブロックを書き足す（実測で確認）。`next.config.ts` の `agentRules: false` で防いでいる。この行を消すと、また書き足される。同じ趣旨の指示は、代わりに `doc/指示.md` に書いてある。
- 初期設定で Cache Components と Partial Prefetching が有効。データ取得は既定で動的で、キャッシュしたい箇所に `use cache` を付ける。動的な要素を入れるときに確認する。

## モックの実装

- 動的にするときは `data/site.ts` の `news` を置き換える。
- ダミー文言の文字数は元の文に揃えている。文字数を変えると折り返しが変わり、高さがずれる。
- PC幅（1025px〜）は元サイトと同じく `min-width: 1370px`。1025〜1369pxでは横スクロールが出る。
- 元サイトと変えた点: スライダーの矢印は作っていない（元サイトは白色で見えない）。最後のスライドの次は巻き戻して先頭へ戻る。全画面メニューの高さは下端が切れないよう調整した。子メニューの開閉はスマホ幅だけ。

## 確認のしかた

- 元サイトとの比較は、Chromeで同じ幅に揃えて各ブロックの座標を測って行う（1440 / 900 / 500px）。
- Chromeのウィンドウは幅500pxまでしか縮まず、縮まないこともある。スマホ幅は、元サイトのページ内にJSで同じサイトのiframe（幅390pxなど）を置けば確認できる（`frame-ancestors 'self'` なので同じサイト内なら表示される）。
- サイト名や記事の中身に元サイトの文言が混ざっていないかは、表示文字列を元サイトのHTMLと照合して確認する。カテゴリ名とボタンなどの文言は対象外。

## 参考元サイトのお知らせ（2026-11-06に調査）

公開ページだけからの調査で、管理画面は見ていない。全記事を1秒1件で取得して集計した。

### 仕組み

- 別々のWordPressが3つある（メイン `/`、一般向け `/rheuma/`、医療関係者向け `/senmon/`）。それぞれがお知らせの投稿タイプ `news` を持つ。REST APIには公開されていない。
- 1記事の項目: タイトル、公開日、カテゴリ1つ、リンク先URL（推測）、本文（自由入力のHTML）。
- リンク先があれば一覧から直接そこへ飛び、なければ `/news/{id}/` へ飛ぶ。直リンク記事にも `/news/{id}/` は存在し、ほとんどは本文が空。前後リンクでもそこに行き着く。
- トップは新しい順に5件、一覧は10件ずつ。ページ送りは現在のページの前後2つまで番号を出す。
- サイト間の連携はなく、手作業で登録しているらしい（更新時刻が数分ずれる、順番が一定でない、タイトルの表記に差がある）。
- 例: 公開講座1件につき、`/rheuma/` の講座ページ、`/rheuma/` のお知らせ、メインのお知らせの計3記事を作っている。
- お知らせとは別に、メインのスライダー（4件）と `/senmon/` のPickup（7件）も更新先。財団ニュースの新刊は、両サイトのお知らせと、この2枠の計4か所に出ている。

### 3サイトの違い

詳細ページの構成は同じ（タイトル、日付、本文、前の記事へ、一覧に戻る、次の記事へ）。

| | メイン | `/rheuma/` | `/senmon/` |
| --- | --- | --- | --- |
| 見出し | お知らせ | What's new | What's new |
| カテゴリと色 | 財団情報 `#1d85cc`、一般・患者さん情報 `#ff9baf`、医療関係者情報 `#00aaaa` | NEWS `#ff9baf`、講演会 `#46c6da`、疾患情報 `#20b067` | NEWS `#0056ad`、リウマチ専門職 `#1c85cc`、助成、医学賞等 `#00aaaa` |
| バッジの幅 | 160px | 100px | 185px |
| 一覧へのリンク | もっとみる | 一覧はこちら | もっとみる |
| 絞り込みボタン | あり | なし | あり |
| カテゴリ別ページ | あり | 白紙（200で0バイト） | あり |
| バッジのリンク | あり | なし | あり |

- スマホ幅（390px）の一覧と詳細は、3サイトでほぼ同じ作り。違いは色、カテゴリ、文言、サイト名の部分と、`/rheuma/` の吹き出しと丸い飾り。新着欄は違い、メインは枠付き、`/rheuma/` はカード、`/senmon/` は区切りのないリスト。
- トップの高さ: PC幅でメイン約2,100px、サブサイト約4,150px。スマホ幅でメイン約3,800px、サブサイト約5,100〜5,200px。
- ヘッダー内のリンク数: メイン44、`/rheuma/` 65、`/senmon/` 74。

### メインの測定値（幅1440px）

- ページタイトルの帯: 高さ160px、背景 `#f2f2f2`。`h1` は明朝36px、`#0056ad`。
- 本文の左右の余白は100px。
- 一覧の絞り込みボタン: 160×49px、枠線2px `#0056ad`、角丸5px。
- 一覧の行: 文字16px、下の余白20px。バッジは高さ29px、文字15px、角丸4px。タイトルは `#0056ad` の下線付き。
- ページ送り: 約34px四方、枠線1px `#0056ad`。現在のページは `#0056ad` の背景に白文字。
- カテゴリ別ページ: 絞り込みボタンの代わりに `h2`（36px、太字）を置く。パンくずは HOME、カテゴリ名。
- 詳細: タイトルは36px太字、下の余白60px。日付は `2026-08-03` の形式で、一覧の `2026年08月03日` とは違う。`h3` は24px、`#0056ad`、左に線。段落の下の余白は16px。
- 詳細の「一覧に戻る」: 256×50px、`#0056ad`、角丸25px、文字18px。
